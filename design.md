# Android Flashing Tool — final UI system

Version 1.1.0. Decentralized.Host local operations application.

Deep navy operational surfaces, restrained cyan/blue/violet branding, subtle glass panels, compact readable typography, a persistent desktop sidebar and responsive mobile navigation. Hero: “Flash. Recover. Customize.” The illustrative phone is branding rather than telemetry.

Navigation surfaces: Flash Workspace, Devices, Firmware Inspector, Operation Evidence, Settings, Setup & Guide. The inspector directs the user to the signed package workflow. Settings reads actual runtime capabilities and exposes unavailable functions clearly.

Device cards distinguish detected, disconnected, unauthorized and unknown states. Missing measurements remain Unknown. Firmware inspection requires the complete independently trusted archive hash and a locally provisioned publisher public key. Machine checks are not checkboxes. Backup and risk acknowledgements are separate human choices.

Primary flow: inspect package → validate device/partitions → review plan → approve exact plan → execute writes → export evidence. The review dialog shows device serial, firmware hash and every explicit partition. Plans expire; approvals are one-use and short-lived. No guessed partitions, automatic wipe, unlock, relock or reboot.

Operation progress reports completed partition writes; it does not invent a time estimate. Fastboot acknowledgements result in “writes completed, unverified.” Signed evidence attests recorded execution, not successful boot. Interrupted records show UNKNOWN outcome and do not resume automatically.

Visible focus styles, semantic controls, keyboard firmware selection, native dialog focus containment and live activity announcements support accessibility. Screens below 760px use stacked cards and horizontal navigation. No external font or analytics requests are required.

The raster reference guides visual direction. Product labels and available capabilities in the running application are authoritative.
